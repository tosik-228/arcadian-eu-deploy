# Arcadian: управление галереей и расценками

Пользовательская админка содержит **два раздела**: работы и расценки. Вход — пароль + код приложения-аутентификатора; предусмотрено 10 одноразовых резервных кодов. Интерфейс — на русском. Публичные страницы — EN, PL, NL; пустые переводы используют общий текст.

## Работа редактора

- **Работы**: название, описание, отделка/реновация, фасады или электрика; город и год необязательны. До 10 фотографий за одну загрузку, до 60 в работе. Подписи, порядок, замена и удаление доступны в карточке. Для публикации нужны название, описание и хотя бы одна фотография.
- **Расценки**: штат / самостоятельный специалист / бригада; точная сумма или диапазон в EUR, единица расчёта, свой автомобиль и инструмент. Для штата — зарплата брутто, для субподряда — счёт без НДС. По умолчанию ставка внутренняя. На сайт попадают только одновременно публичные и опубликованные записи.
- Черновик и архив закрыты для посетителя, включая ссылки на фотографии. Снятие с публикации действует при следующем запросе; публичный CDN-кэш изображений намеренно выключен.
- «История» показывает автора и правки, позволяет восстановить описание, состояние и цену. История работы не восстанавливает состав фотографий. Старые файлы сохраняются для восстановления из копии; автоматического удаления нет.
- Конфликт двух вкладок отклоняется с понятным сообщением; новая правка не затирается молча.

## Архитектура

Статический сайт сохраняет нынешнее размещение. Отдельный Django 5.2 LTS сервис обслуживает `/admin/` и три публичных маршрута чтения. PostgreSQL 17 хранит данные, права, серверные сессии, историю и ограничения входа. В выбранном production-размещении админка и PostgreSQL работают на существующем дроплете Werfvolt. Фотографии хранятся в постоянной закрытой папке `/opt/arcadian-content/media`. Вариант Managed PostgreSQL/Spaces сохранён в коде как отдельный режим, но для этого выпуска не используется.

JPEG, PNG, WebP, AVIF и HEIC проверяются по содержимому. Лимит: 20 МБ на файл, 60 МБ на одну загрузку, 24 млн пикселей и 8192 пикселя по стороне; анимация и SVG отклоняются. Для каждого фото создаются WebP 480×360, 960×720 и вариант до 2400 пикселей. Геометки, EXIF, XMP и исходное имя удаляются. Исходник не сохраняется. Обработка изображений сериализована между двумя процессами приложения, чтобы большие фотографии не превышали лимит памяти. Публичный ответ не содержит ключи хранилища и персональные данные редактора.

Продакшен: HTTPS, HSTS, строгие cookies, CSRF, Argon2, обязательный второй фактор, блокировка после пяти неудачных попыток на 15 минут и явный список CORS-источников. Нет публичного API записи. Учётная запись редактора не управляет пользователями или инфраструктурой.

Сервис работает без root. Образ Python и PostgreSQL закреплены по digest; Python зависимости закреплены с хешами, зависимости проверок сайта — в package-lock. SQL-учётная запись сервиса не имеет прав DDL и не может удалять/редактировать историю. Копии используют отдельную SQL-учётную запись только для чтения. Миграции выполняются перед выпуском с отдельными полномочиями.

## Локальный запуск

Требуются Python 3.12, Node 22+, Docker Engine/Colima. Режим Docker не переключается глобально. В этом рабочем окружении используется `colima-arcadian-cms`.

```sh
npm ci --ignore-scripts
npm run cms:setup
python3.12 -m venv cms/.venv
cms/.venv/bin/python -m pip install --require-hashes -r cms/requirements.txt
DOCKER_CONTEXT=colima-arcadian-cms docker-compose --env-file cms/.env -f cms/compose.yml up -d --wait
cms/.venv/bin/python cms/manage.py migrate --noinput
cms/.venv/bin/python cms/manage.py grant_runtime
cms/.venv/bin/python cms/manage.py collectstatic --noinput
npm run cms:bootstrap
cms/.venv/bin/python cms/run-local.py
```

В другом терминале: `npm run preview`.

- Админка: http://127.0.0.1:8057/admin/
- Галерея: http://127.0.0.1:8173/gallery/
- Электрика: http://127.0.0.1:8173/electrical/
- Расценки: http://127.0.0.1:8173/rates/
- Первый вход: приватный `cms/.state/first-login.html`. Сохранить пароль/резервные коды в менеджере паролей и удалить файл после настройки. Не публиковать его.

`.env`, `.state`, локальные фотографии, приватные ключи и копии исключены из Git и Docker build context. Повторная настройка не сбрасывает существующие пароли, данные и 2FA.

## Резервные копии

`content_backup` создаёт согласованный PostgreSQL-снимок через REPEATABLE READ: содержание, пользователей, права и историю. Сессии и временные записи блокировки входа не переносит. Включает действующие и исторические изображения с SHA-256; архив шифруется `age` **публичным** ключом. Приватный ключ расшифровки хранится отдельно от сервиса.

```sh
cms/.venv/bin/python cms/manage.py content_backup --output cms/.backups
cms/.venv/bin/python cms/verify-backup.py
```

Первой команде нужна переменная `BACKUP_AGE_RECIPIENT`. Вторая создаёт локальную пару ключей, выполняет реальное восстановление в отдельную временную PostgreSQL-базу, сверяет записи и байты фотографий и удаляет только свои тестовые данные. Для `age` необходим одноимённый CLI.

На дроплете ежедневное шифрованное копирование запускает отдельный systemd timer: 02:15 UTC, с задержкой до пяти минут. Хранятся две последние успешные копии; незавершённая копия не заменяет последнюю исправную. Перед запуском проверяется свободное место. Независимый SSH-ключ с принудительной командой разрешает только чтение последней шифрованной копии, без shell и туннелей. Mac забирает её каждый час и проверяет размер и SHA-256. На Mac — до 14 копий в пределах 2 ГБ; приватный age-ключ не передаётся на дроплет.

Копирование на Mac работает, когда компьютер включён и пользователь вошёл в систему. Уже включённые ежедневные копии DigitalOcean сохраняют весь дроплет вне его диска в течение семи дней. Начальная цель RPO для логических копий — 24 часа. Сбой задания виден в `systemctl status arcadian-content-backup.service` и локальном журнале Mac; отдельное внешнее оповещение пока не настроено. Время восстановления на реальном объёме фотографий пока не измерено.

`content_restore` принимает только пустую базу с именем `restore_*`, проверяет все контрольные суммы до записи и отказывается перезаписывать существующих пользователей/фотографии. Действующую базу восстанавливают через отдельный стенд и последующее переключение.

## Размещение на существующем дроплете

Сайт `arcadian-eu.com` и `www.arcadian-eu.com` остаётся в существующем App Platform. Только `cms.arcadian-eu.com` указывает на `46.101.148.208`. Форма продолжает использовать прежний API Werfvolt.

- `/opt/arcadian-content` — собственный Compose-проект, база PostgreSQL, media, шифрованные копии и конфигурация с правами 600/700.
- PostgreSQL слушает только общий Unix socket. TCP, публичные порты и доступ к MySQL Werfvolt отсутствуют. Вход в socket тоже требует пароль SCRAM.
- Caddy Werfvolt получает отдельный `docker-compose.override.yml`. Он добавляет только общий прокси и внешнюю сеть Arcadian. Обёртка импортирует штатный live/maintenance Caddyfile и отдельный маршрут CMS. Переключение maintenance и будущий выпуск Werfvolt сохраняют маршрут Arcadian.
- Приложение: UID/GID 10001, корневая файловая система только для чтения, capabilities сняты, tmpfs 256 МБ, 2 процесса, лимит 1 ГБ RAM / 0.75 CPU. База: максимум 30 соединений, 512 МБ RAM / 0.5 CPU.
- `deploy/setup.py` создаёт свежие production-пароли и конфигурацию **на Mac**. На сервер передают только разрешённые env-файлы, образ и конфигурацию; `backup-identity.txt` всегда остаётся на Mac. Первый вход в production сохраняют отдельно от локального файла.
- Перед обновлением: свежая копия, локальные серверные и браузерные проверки, идентичный образ по SHA-256, миграции отдельной SQL-ролью и проверка готовности. Для выпуска статических страниц требуется готовая CMS и переменная `CMS_PUBLIC_URL=https://cms.arcadian-eu.com`.

Дроплет расширяется с 1 CPU / 2 ГБ до 2 CPU / 4 ГБ. Диск остаётся 50 ГБ: это сохраняет возможность обратного уменьшения вычислительных ресурсов. Тариф compute — **$24/месяц**; уже включённые ежедневные копии — 30%, итого **$31.20/месяц**, до налогов и превышения включённого трафика. Существующий тариф статического сайта остаётся отдельным.

Источники: [Droplets](https://www.digitalocean.com/pricing/droplets), [резервные копии](https://docs.digitalocean.com/products/backups/details/pricing/), [изменение размера](https://docs.digitalocean.com/products/droplets/how-to/resize/).

## Проверки

```sh
npm run test:cms
npm run test:browser
TURNSTILE_SITEKEY=ci_only_invalid_sitekey_20260824 CMS_PUBLIC_URL=https://cms.arcadian-eu.com sh static-site/build-turnstile-site.sh
npm run check:html
npm run check:links
```

Проверка ссылок направляет canonical/hreflang на локальную сборку; проверяет новые страницы до их публикации. Тесты браузера создают отдельного временного редактора/проекты/ставки, проходят реальную загрузку и удаляют свои данные. Для браузерной проверки предварительно запустить CMS/preview и установить Chromium: `npx playwright install chromium`.

Свидетельства локальных проверок сохраняются в приватной `cms/.state`: серверные тесты, восемь браузерных сценариев, проверка ролей и реальное восстановление базы и 12 вариантов изображений. Это не свидетельство production-развёртывания. Состояние production фиксируется отдельным отчётом после DNS/TLS, запуска, копирования и приёмки сайта.
